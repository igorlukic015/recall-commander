# Phase 0 intake retrospective

## What happened
Phase 0 ran in legacy mode on a .NET 10 repo whose MVP 1 had just been squash-merged to `main` (PR #2). The ADOS guide and templates weren't present in the repo, so the state and tribal-knowledge files were built from the agent spec. The first scan ran on `mvp-1`. The user then merged to `main`, and work moved to `inception/phase-0` branched from `main`.

## What went well
- The existing `Docs/` set is rich and already records decisions inline (question identity, answer separator), which makes tribal-knowledge mining reliable.
- Hard rules were consistent across `CLAUDE.md`, `AGENTS.md`, `opencode.json` and `.claude/settings.json`.
- Comparing `AGENTS.md` against the csproj references surfaced real drift (X1).

## Improvement pattern to repeat
Compare agent-instruction claims with the build graph (csproj and package references) during Phase 0. Documentation drift shows up early and cheaply that way.

## Caution
After the squash merge, `git log main` shows only 7 commits. The decision-bearing granular commits survive only on the `mvp-1` branch. If that branch is deleted, the commit-sourced tribal knowledge loses its provenance.

## Why it matters / ADOS framework proposal
The bootstrapper assumes `doc/guides/project-inception.md` and `doc/templates/*` exist in the target repo. A first-run legacy project won't have them. Proposal: either ship the templates with the plugin and install them during Phase 0, or make Phase 0 explicitly allowed to defer template installation to Phase 5 and reconcile then.
